# Toolformer：讓模型自我學會何時使用工具
## 研究問題
語言模型可能不擅長精確計算、查詢外部知識或取得即時資訊。若每次工具使用都需要大量人工標註，資料製作成本高。Toolformer 探討能否透過少量工具示範，讓模型自行提出候選 API 呼叫，再以自監督訊號篩選有幫助的呼叫。
## 方法流程
1. **少量示範**：提供工具名稱、輸入格式與少量使用例子。
2. **候選呼叫生成**：模型在語料的候選位置產生 API 呼叫及參數。
3. **執行工具**：實際執行候選呼叫，取得工具回傳結果。
4. **效用篩選**：比較加入工具呼叫及結果前後，模型對後續文字的語言模型 loss。若工具結果能讓後續文字更容易預測，才保留該呼叫。
5. **資料增強與微調**：將保留的呼叫與結果插入語料，再訓練模型學習工具使用。
6. **推論時執行**：模型產生工具呼叫時暫停生成、執行工具、插入結果，再繼續生成。
## 技術重點
Toolformer 不只是教模型 API 語法，而是嘗試學習「何時呼叫、呼叫哪個工具、傳入什麼參數，以及如何利用結果」。loss 降低是工具呼叫效用的代理訊號，不代表工具結果在現實任務中必然正確。
## 工具與評估範圍
論文研究計算機、問答、搜尋、翻譯與日曆等工具，並以 GPT-J 為基礎模型進行工具使用訓練與下游評估。閱讀實驗結果時，應保留論文的模型規模、資料與任務條件，不宜將結果泛化為所有模型都能自動學會任意工具。
## 限制
- 自監督 loss 是代理指標，不等同真實任務成功率或安全性。
- 工具需能被執行，且輸入輸出可被序列化為模型可處理的內容。
- 真實部署仍需權限控管、參數驗證、錯誤處理與副作用管理。
## 與 ReAct 的差異
ReAct 著重推理與行動如何在執行時交錯；Toolformer 著重透過資料生成與微調，讓模型學習工具呼叫行為。兩者位於不同設計層次。
