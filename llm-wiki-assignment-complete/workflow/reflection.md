## 本次流程觀察
在整理五篇論文時，最容易出現的問題是把不同研究都概括成「讓 LLM 使用工具」，而忽略它們處理的是不同層次：ReAct 是推理與行動交錯；Toolformer 是自監督工具使用訓練；Gorilla 是 API 文件檢索與呼叫生成；ToolLLM 是大量 API 的多步驟任務；AgentBench 是跨環境評估。
## 哪個節點最容易出錯？
研究定位與來源抽取節點。若只讀摘要，很容易把方法、訓練流程、執行架構與評估基準混為一談。
## 把檢查往前移到哪裡？
把「研究問題／方法類型辨識」及「主張—來源對照」提前到正式撰寫之前，先確認每篇論文真正回答的問題，再生成文章。
## 是否修改 workflow / graph？
有。相較於單純「讀資料→整理→寫文章」，增加了生成前的證據檢查與生成後的內容檢查；未通過時回到來源抽取或文章修訂。
